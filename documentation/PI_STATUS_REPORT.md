# BioUnlearn: Status Report

**Purpose of this document**: a self-contained summary of research direction, proposal, and findings to date, written for reporting to a collaborator/PI. It synthesizes the fuller working documents in this folder (`MASTER_RESEARCH_PLAN.md`, `NOVEL_METHODOLOGY_OGDA.md`, `OGDA_REPRODUCIBILITY.md`, `groundtruth_sources_dr_vindo_directions.md`) rather than replacing them.

---

## 1. The research question and why it matters

Clinical LLMs are fine-tuned on medical text that includes facts which later turn out to be wrong, retracted, or unsafe: guidelines get reversed (aggressive glycemic control in the ICU was later shown to increase mortality — the NICE-SUGAR reversal), drugs get withdrawn (rofecoxib/Vioxx), and hormone therapy recommendations were reversed after the Women's Health Initiative trial. Machine unlearning — deliberately removing a fact from a trained model's weights — is the leading technical approach to this problem, but it has been developed and validated almost entirely on **general-domain benchmarks** (TOFU, WMDP, MUSE) built from fictitious or clearly-hazardous content with clean forget/retain boundaries.

**Our thesis**: that clean separation does not exist in clinical knowledge — a forgotten fact (e.g., an old dosing guideline) sits one edge away in a medical ontology from dozens of facts that must be *retained* (drug class, related indications, contraindications) — and every representative unlearning method fails as a result, in ways invisible on the benchmarks the field currently uses.

## 2. What we're proposing (five contributions, per `MASTER_RESEARCH_PLAN.md` Section 2)

1. **A diagnostic study** showing representative unlearning methods (GA, NPO, RMU, and others) fail on clinically-relevant axes that don't show up on TOFU/WMDP.
2. **PTGC (Provenance-Tiered Ground Truth Construction)** — a new dataset methodology that grades every forget/retain instance by how real its source is (peer-reviewed literature record vs. ontology-derived vs. LLM-invented), rather than the field's current default of treating all synthetic benchmark data as equally trustworthy. This is a reusable contribution independent of our specific benchmark.
3. **Four evaluation metrics**: OCD (Ontological Collateral Damage), DEF (Directional Erasure Fidelity), CLMI (Concept-Level Membership Inference), and EWEF (Evidence-Weighted Erasure Fidelity — new, uses each source's clinical evidence-certainty grade to weight how much credit a correction deserves).
4. **A methodology framework** (originally OGFR/DGP, now centered on OGDA — see Section 4 below) for unlearning that's ontology-aware rather than treating each fact in isolation.
5. **BioUnlearn-Bench**: a benchmark built with real, citation-backed clinical knowledge reversals rather than LLM-invented ones.

Deliberately kept as a separate versioned set rather than overwriting `data/splits/`, specifically so it doesn't silently invalidate every baseline number already reported above.

The IFE-side collateral pattern (56-example set, unchanged from pilot) replicates exactly as before — full DEF collapse to 0.0 for aspirin/rosiglitazone/Vioxx, HRT's exception holding at 0.016 (matching its own baseline almost exactly) — which is expected since that specific measurement didn't change. **Honest read**: this is not evidence OGDA "stopped working" — each checkpoint's edit is deliberately surgical, touching only one concept's ontology-anchored subspace, so 272 of 273 v2 examples are about entirely unrelated topics an aspirin-specific edit was never going to move. It does mean the pilot-scale own-scenario effect was only ever detectable because the pilot eval set happened to be narrow enough for a single-concept edit to register in the aggregate — **this makes the already-flagged "concept-specific eval subset" item (Section 7) not just a nice-to-have but a precondition for OGDA's own-scenario claim to be measurable at benchmark scale at all.**

Used the plan's own pre-approved fallback for exactly this case (`MASTER_RESEARCH_PLAN.md` Section 4.2: synthetic PAC generation is explicitly sanctioned when "no real record can exist by construction," provided it's disclosed as such). This is the same structural point TOFU is built around (fine-tune on fictional data first, then test whether unlearning removes it) — so a PAC "contamination" fine-tune stage (`configs/experiment/finetune/bioun_pac/default.yaml`, SFT BioMistral-7B on the PAC forget-set to actually make it produce the rare/identifying answers) was added as a prerequisite before GA/NPO/RMU/OGDA against PAC can test anything meaningful. Running now.

All 396 of Herrera-Perez et al. 2019's reversals extracted directly from the paper's supplementary data (not just a sample), plus the existing 10 from Prasad et al. 2013. Genuine peer-reviewed, literature-grounded ground truth, not LLM-generated.
- **Gate 0 (verification validity check)**: confirmed our probing methodology (CLMI) can actually distinguish concepts before trusting it as a measurement tool, via label-swap and paraphrase controls.
- **Gate 2 (baseline diagnostic matrix)**: Gradient Ascent (GA), NPO, and RMU all run successfully end-to-end on **both** BioMistral-7B (clinical model) and Llama-3.1-8B-Instruct (non-clinical cross-model control) — 12 total runs, all real and non-degenerate, after fixing a chain of real infrastructure bugs (Section 5).
- **Cross-model finding**: RMU's effect strength is sharply model-dependent at *identical* hyperparameters — near-zero on BioMistral-7B, but a large, real, scenario-specific effect on Llama-3.1-8B (targeted scenario moved substantially, untargeted stayed exactly at baseline). Method-sensitivity rankings from a single-model pilot don't generalize — a genuinely useful methodological finding for the paper's baseline comparison section.
- **Cross-dataset comparison**: the paper's diagnostic thesis compares BioUnlearn-Bench against TOFU/WMDP — this had never actually been run until now. GA, NPO, and RMU all now have real, non-collapsed TOFU results at a properly-tuned matched dose (found by first reproducing GA's collapse at TOFU's own standard 10-epoch config, then locating the sweet spot at 1 epoch). Two real findings: (1) GA's catastrophic collapse is **not** BioUnlearn-Bench-specific — the identical failure mode occurs on TOFU too at aggressive settings, confirming it's a general property of the method. (2) RMU's relative gentleness, found on BioMistral, does **not** hold on TOFU — there RMU is by far the *most* aggressive of the three methods, consistent with the earlier BioMistral-vs-Llama-3.1-8B divergence.
- **Why the OCD-style comparison can't be run on TOFU — settled, not just flagged (new)**: the natural next question was whether TOFU could also test the paper's actual core diagnostic claim — that clinical concepts' ontological entanglement causes *collateral* damage on retain-critical neighbor concepts. Checked directly against the dataset itself rather than left open: TOFU's forget10/retain90 split is disjoint at the whole-author level (400 = 20 authors × 20 facts; 3600 = 180 authors × 20 facts; verified zero author-name overlap between the splits directly). Every fact about a given fictitious author sits entirely on one side of the split — TOFU has no cross-author relational structure at all (each author's biographical facts are independently generated fictions), so there is no analog to a UMLS drug-class hierarchy or ICD comorbidity graph for an edit to leak into. Full writeup with reproduction code in `documentation/TOFU_STRUCTURAL_ANALYSIS.md`. **This is a positive finding, not an unresolved gap**: TOFU cannot pose the OCD-style question by construction, independent of whether anyone ran the experiment — which is itself evidence that a UMLS-graph-grounded benchmark (BioUnlearn-Bench) is a necessary contribution, not a redundant one, and should be stated as such in the paper.
- **Adjacent-method baseline: RAG-suppression (new)** — the obvious non-weight-editing alternative a reviewer will ask about ("why not just RAG this?"). Implementation: no weights touched at all; a retrieved-correction context (built from each instance's own `reversal_reason`/`ground_truth_source`/`retain_answer` — what a real retriever would plausibly surface) is prepended only to the targeted scenario's prompts, with the untargeted scenario left as plain baseline prompts (nothing relevant would be retrieved for an unrelated question). Real result, run on the full 58-example RGU / 56-example IFE eval sets, base BioMistral-7B: **DEF on the targeted scenario is 0.585 (RGU-targeted) / 0.547 (IFE-targeted) — 3-4x higher than every weight-editing method tested (GA/NPO/RMU/OGDA all scored DEF in the 0.13-0.20 range)**, and the untargeted scenario shows **no collateral movement outside the same noise floor already established elsewhere in this project** (e.g. IFE-targeted run's RGU_fa=0.724 vs. untouched baseline's 0.741 — well within the seed-to-seed noise band measured in Section 4). This is an honest, load-bearing finding, not a favorable-looking throwaway: it means simple retrieval-based correction dominates weight-editing on both FA/DEF *and* collateral safety in this setting, which sharpens the paper rather than undercutting it — the case for weight-editing methods (OGDA included) now has to rest on properties RAG can't offer (no runtime retrieval dependency, robustness to prompt-injection/context-stripping, generalizing to paraphrased prompts without a matching retrieval trigger, working when extraction attacks bypass the retrieval layer entirely), not on raw behavioral metrics. Full numbers: `data/gate2_results/RAG_suppression_RGU_summary.json`, `RAG_suppression_IFE_summary.json`.
- **Adjacent-method baseline: ROME knowledge editing (new)** — a single rank-one edit per instance (layer 5, `model.layers.5.mlp.down_proj`, off-the-shelf `mistral-7b` hyperparameters from `zjunlp/EasyEdit`, no tuning), applied against BioMistral-7B one instance at a time (edit → generate+score on the original clinical question → restore original weights → next instance). Required first reformulating each open-ended clinical Q&A instance into the short subject/target-fact triple ROME actually edits (`stage_a_umls/rome_reformulate.py`), since ROME edits a specific short completion, not a free-form answer. Real result, run at full scale (49/56 RGU and 34/44 IFE instances successfully scored; the remainder hit real GPU-memory OOM on this shared 39GB card — the other tenant was holding ~20GB the whole time — not a logic failure, and every OOM was caught without corrupting the run once the eval script was made crash-safe, see Section 5): **RGU target DEF = 0.061, IFE target DEF = 0.0 exactly (0 of 34 successfully-edited IFE instances produced the correct new answer)**. FA rises in both (RGU 0.86, IFE 0.94 — the model does stop giving the old answer) but accuracy on the new answer stays near zero (RGU 0.12, IFE 0.0 exactly) — the edit mostly breaks the old fact without ever landing on the replacement. **This is the weakest result of every method tested in this project**, well below GA/NPO/RMU/OGDA (0.13-0.20) and far below RAG-suppression (0.55-0.58). Collateral damage is low in both directions (RGU-targeted collateral DEF=0.005; IFE-targeted collateral RGU_def=0.201, actually slightly *above* untouched baseline's 0.192, i.e. no real collateral effect) — ROME is "safe but ineffective" here, the opposite failure mode from GA's "effective but destructive" collapse. **Honest read, not glossed over**: this most likely reflects ROME/MEMIT's design mismatch with this task — it was built and tuned for short factual triples ("The Eiffel Tower is in ___"), not our longer, free-form clinical answers, and the hyperparameters used are the community-published Mistral-7B defaults, not tuned for this domain at all. This is a real limitation of applying ROME out-of-the-box to open-ended clinical QA, worth stating as such — not a claim that knowledge editing categorically cannot work here, and not a flaw in the comparison methodology itself. Full numbers: `data/gate2_results/ROME_RGU_summary.json`, `ROME_IFE_summary.json`.

## 4. The novel method: OGDA, and an honest read on where it stands

**OGDA (Ontology-Guided Directional Ablation)**: a training-free method that identifies the direction/subspace in a model's activation space corresponding to a specific fact, then surgically removes only the component of that direction that *isn't* shared with clinically-related concepts that must be retained (built from real UMLS/RxNorm ontology neighbors, not guessed). Checked against ~15 recent related papers (Arditi et al. 2024's activation-ablation technique, NSRU, PISCES, SAGO, and others) — the specific combination (ontology-anchored protected subspace + training-free directional ablation + applied to clinical guideline reversal) is not claimed elsewhere.

**What we've actually verified, in order:**

| Test | Result |
|---|---|
| Does the entanglement problem this method targets actually exist? | **Yes, quantitatively.** The aspirin-cardiovascular concept's direction overlaps its clinical-neighbor subspace at cos²=0.985 — measured directly, not assumed. |
| Does the ablation mechanism actually execute (not a silent no-op)? | **Yes, verified mechanically** — caught and fixed a real bug where our own verification code was reading stale pre-ablation activations. |
| Is the subspace construction mathematically sound? | Found and fixed a real circularity bug (the "forget" and "protected" subspaces were accidentally defined as the same thing by construction) — now genuinely independent. |
| Does a parametric probe (CLMI) detect erasure? | **No** — even a fairness-matched, capacity-restricted probe still perfectly separates the ablated concept from a near-synonym. Root-caused as likely a limitation of mean-pooled whole-sequence probing against near-synonyms (it can key on any remaining word-choice difference), not necessarily proof the ablation failed — this is itself informative about the paper's own Failure Mode 3 (verification is hard) thesis. |
| Does actual generated text change (FA/DEF, the behaviorally decisive test)? | **Yes — real movement, but not clean targeted erasure.** Tested across all 4 real-graph concepts, not just aspirin. 3 of 4 show a consistent pattern (the concept's own scenario moves more, sometimes collapsing DEF to 0); one (HRT) breaks the pattern entirely, moving in the opposite direction. Important caveat found while aggregating: observed FA deltas correspond to exactly 1-4 individual examples flipping on a 56-58-example eval set, not a smooth aggregate effect — real, but not yet a statistically robust effect size (Section 6). |
| **Is the effect specific to the ontology-anchored direction, or would any similarly-sized edit cause it?** | **Partially — precise finding, corrected once from an initial overclaim.** First test (1 random seed) suggested a clean "yes." Running 2 more random seeds to build an actual distribution overturned that: FA alone has enough seed-to-seed variance under random-subspace ablation that it's *not* a reliable differentiator (random seeds produced FA swings as large as or larger than real OGDA's). DEF tells a different, more robust story — see below. |

**Statistical comparison** (aspirin concept; z-scores of real OGDA's result against the mean±std of 3 random-subspace control seeds, same rank/layers/mechanism):

| Metric | Random-control distribution (delta from baseline, n=3) | Real OGDA's delta | z-score | Distinguishable from random? |
|---|---|---|---|---|
| RGU FA | -0.029 ± 0.020 | +0.017 | 2.31 | Borderline |
| RGU DEF | +0.001 ± 0.007 | -0.035 | **-5.44** | **Yes, clearly** |
| IFE FA | +0.030 ± 0.037 | +0.054 | 0.64 | **No** |
| IFE DEF | +0.001 ± 0.001 | **-0.015 (full collapse to 0.0)** | **-23.38** | **Yes, clearly** |

Corrected finding: **FA is not a reliable signal that the ontology-anchored direction matters** (an earlier version of this report claimed otherwise, based on only one random seed — flagging the correction openly rather than letting it stand). **DEF is** — real OGDA is a large, clear statistical outlier on DEF for both scenarios, especially the complete collapse to exactly 0.0 on the untargeted scenario, which no random seed came close to. Since DEF requires the model to both stop matching the old answer *and* correctly produce the retain-consistent one, this is a more demanding and apparently more reliable signal than FA alone. The claim that OGDA's mechanism is non-generic now rests specifically on this DEF result, not on a blanket statement about the random control — a narrower but more defensible claim.

**Multi-concept replication, then a second correction once real-side variance was measured — now closed on all 4 concepts, not just aspirin**: the random-control distribution is concept-agnostic, so it was first reused as the null distribution for the other 3 concepts' single-seed results — own-scenario DEF looked like a statistical outlier for all 4 concepts (z=-5.44 to -23.38). That analysis, like the original random-control one, compared a **single** real-OGDA sample against a properly-measured (n=3) null distribution. Closing this gap on aspirin first (2 more seeds) **changed the answer** there: IFE DEF dropped from z=-23.38 to z=-1.92, no longer a clear outlier. The same fix has now been run on the other 3 concepts too — 2 more real-OGDA seeds each on rosiglitazone, HRT, and Vioxx, recomputed as genuine n=3-vs-n=3 comparisons (`data/gate2_results/OGDA_multiconcept_n3vn3_statistical_comparison.json`). **The original 4-concept "decisive" claim is retracted, not just caveated**: own-scenario z-scores at proper n=3-vs-n=3 range from 0.49 to 4.47 (only aspirin's RGU_fa, z=4.47, clears conventional significance on its own; the other 3 concepts' own-scenario DEF sit at z=-1.86 to -2.04, right at the edge, not clearly past it). What's genuinely new: two concepts (rosiglitazone, Vioxx) show large, independently significant DEF suppression specifically on their **collateral/untargeted** scenario (z=-3.07 and z=-6.28), meaning OGDA does more untargeted damage than a random edit of the same size for those concepts. HRT's collateral exception is now confirmed reproducible (z=+0.68, the lone positive DEF z-score in the whole table). Across all 8 own+other DEF comparisons, 7 point the same direction (real DEF below random-control) — corroborating context, not an independent formal test, but not nothing either.

**Bottom line on novelty, updated again now that all 4 concepts have proper n=3 vs. n=3 statistics**: the 4-concept replication claim has now been re-run at full rigor (`OGDA_multiconcept_n3vn3_statistical_comparison.json`), closing the exact gap the previous update flagged as open. The original "decisive" framing (z=-2.70 to -23.38, clean DEF collapse in 3 of 4 concepts) does not survive and is retracted, not merely caveated — it was the same n=1-vs-n=3 artifact already caught on aspirin, now confirmed on the other 3 concepts too. What replaces it: aspirin's own-scenario RGU FA remains the single cleanest individually-significant result (z=4.47); two concepts (rosiglitazone, Vioxx) show large, independently significant DEF suppression specifically on their **collateral** (untargeted) scenario, not their own target — a real and arguably more interesting finding than the original own-scenario story, since collateral damage on ontology-neighbor concepts is closer to the paper's actual thesis than clean targeted erasure is; HRT's collateral exception is now a confirmed reproducible anomaly rather than a single-run fluke. This is a smaller, more defensible claim than the original 4-concept "decisive" framing, arrived at by directly closing a gap the project's own documentation had flagged as open rather than leaving it unresolved. The proposal remains genuinely original and has now been stress-tested at proper statistical rigor across all 4 tested concepts, not just one — what's changed twice now is which specific number we can defend, not whether the underlying investigation has been careful.

**Layer/rank sweep, run in full, with an honest correction of its own**: ran a systematic sweep (4 CLMI screening points, then direct behavioral testing on the most promising candidates) to see whether a smaller/differently-placed edit could avoid the collateral IFE collapse while keeping RGU's own-scenario signal. Narrowing to late layers only (20-28, then 24-28) made the IFE collapse disappear entirely at 5 layers — this initially looked like a precise mechanistic localization to layers 20-23. **Tested that claim directly and it failed**: ablating everything *except* layers 20-23 (21 other layers) still produced the full collapse, meaning those 4 layers aren't uniquely responsible. Corrected reading: this is a **breadth/dose threshold effect** (enough layers ablated in aggregate triggers the collapse) rather than a specific causal locus. Retracting the "avoid layers 20-23" fix idea the false localization had suggested. Reported both the apparent finding and its retraction in the working documents, not just the version that held up.

## 5. What had to be fixed along the way (real engineering, not incidental)

The shared A100 GPU here is genuinely shared with other users' unrelated jobs — designed around that constraint rather than around getting exclusive access:

- GA's original hyperparameters caused catastrophic collapse (gibberish output) — root-caused to unconstrained-loss unbounded descent, fixed by matching the literature's step-count-based tuning rather than epoch-based.
- NPO/RMU (which need a frozen reference-model copy alongside the trainable model) were blocked by a fixed ~31GB memory cost regardless of batch size — unblocked by combining LoRA fine-tuning (cuts trainable parameters to 0.6% of the model) with loading the reference model in 8-bit, plus three RMU-specific compatibility fixes this surfaced (module-name matching under LoRA wrapping, a masked-gradient regex bug that would have silently undone the memory savings, and a dtype mismatch from mixing 8-bit and full-precision computation).
- Extending to the larger Llama-3.1-8B-Instruct model hit the same wall again at a higher memory floor — LoRA + 8-bit reference model wasn't enough on its own. Added QLoRA (4-bit base model, 4-bit reference model) as a further, reusable capability — makes any 8B+ model tractable on this shared GPU going forward, not just a one-off fix.
- A cache-key collision bug in the eval pipeline was silently causing one scenario's metrics to leak into the other's — caught and fixed before it corrupted any reported numbers.
- Gold-source harvesting: the paper's own PMC download link is gated behind a JS/proof-of-work check plain scripts can't pass; found the real download path via the publisher's own article API instead. Full extraction cross-checked against the paper's claimed total (396) and matched exactly — a strong sanity check the harvest was complete and lossless.
- First TOFU run caught a real config bug in RMU's own default: the trainable-params regex added earlier specifically for the LoRA case (`.*lora.*`) silently matches **zero** parameters when LoRA isn't active — the first TOFU RMU attempt trained with 0 trainable parameters without erroring. Caught immediately (logged trainable-param count is always checked before trusting a run) and fixed via an explicit override for full-precision runs.
- v2-scale reproduces the same shared-GPU capacity wall harder than before: retraining GA/NPO/RMU against the larger v2 eval set repeatedly hit `CUDA out of memory` (our process needs ~18.7GB, the other tenant holds ~20.7GB steady, the card is 39.39GB total — near-zero margin). A background retry driver's exit-code logging bug made failed retries look like they'd succeeded (`$?` was evaluated after a `$(date)` subshell in the same line, silently capturing the wrong exit status) — caught by checking actual log content (`grep "Result for metric"`) instead of trusting exit codes, a lesson now applied everywhere: never trust a shell exit code without also verifying real output. Fixed with a GPU-aware retry loop that checks free memory before each attempt and verifies success from log content, not exit status.
- Reusing the existing RGU/IFE metric configs directly inside the new PAC eval bundle broke it (`AssertionError: bioun handler not set`) — those configs' Hydra `@package` directive is hardcoded to `eval.bioun.metrics.*`, so reusing them under `eval.bioun_pac` created a stray, handler-less `eval.bioun` node instead of nesting correctly. Fixed the same way the v2 bundle was built correctly the first time: dedicated `_pac`-suffixed copies of each metric config with the right package target.

Full technical detail on all of these is in `docs/bioun_running_notes.md` and `documentation/OGDA_REPRODUCIBILITY.md` (the latter has exact commands to reproduce every OGDA result above from scratch).
